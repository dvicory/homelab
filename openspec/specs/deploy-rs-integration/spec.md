## Requirements
### Requirement: deploy-rs consumes den-generated configs

The `deploy-rs` flake output SHALL consume `nixosConfigurations` generated by the manual output bridge (not the custom DSL or den's auto-generation).
The `deploy.nodes` configuration SHALL reference `inputs.self.nixosConfigurations.<name>` for each deployable host.

#### Scenario: Deploy node references bridge-generated config

- **GIVEN** a host is declared via `den.hosts` and the manual bridge produces `nixosConfigurations.<name>`
- **WHEN** the `deploy.nodes` output is evaluated
- **THEN** the node's `path` SHALL reference the bridge-generated `nixosConfigurations.<name>.config.system.build.toplevel`

### Requirement: deployment metadata via config.deployment NixOS option

Deployment metadata (target IP, SSH user, SSH port, known_hosts path) SHALL be defined as a `config.deployment` NixOS option set, not through the Host Inventory DSL or den's schema.
The `config.deployment` option set SHALL be defined in a shared aspect and per-host values SHALL be set in the host's configuration file.

#### Scenario: Host defines deployment target via NixOS option

- **GIVEN** a host aspect includes the deployment aspect and sets `nixos.deployment = { ip = "172.27.50.17"; sshUser = "daniel"; }`
- **WHEN** the deploy-rs module reads `nixosConfigurations.<name>.config.deployment`
- **THEN** deploy-rs SHALL use the specified IP and user for deployment

#### Scenario: Deploy-rs works independent of generation mechanism

- **GIVEN** `config.deployment` is a standard NixOS option set
- **WHEN** the NixOS configuration is generated by den, clan, or any other mechanism
- **THEN** the deploy-rs module SHALL correctly read deployment metadata from the same `config.deployment` path

#### Mechanism

- `modules/flake/deploy-rs.nix` — adapted to read from `nixosConfigurations.<name>.config.deployment` instead of `config.flake.dlab.hosts.<name>.deploy`
- `modules/aspects/deployment/default.nix` — defines the `config.deployment` option set as a shared aspect
- Per-host values set in `modules/aspects/hosts/<name>/configuration.nix` within the host's `nixos` block
- SSH key handling (SOPS-based, via existing wrappers) continues unchanged
- This approach follows Codys-Wright's deploy-rs integration pattern, not zakuciael's (which doesn't use deploy-rs)
